# 如何管理用户和权限

这篇指南介绍如何创建系统新用户账号、配置其对应的菜单可见与编辑权限、修改密码及进行故障排除。

## 前提条件

- 必须以 `admin`（系统管理员）身份登录。
- 只有勾选了“是否管理员”的用户，或具备 `users` 页面 `can_edit` 权限的用户才能访问并操作“用户管理”页面。

## 创建新用户

1. 点击左侧菜单中的 **【用户管理】**。
2. 点击右上角的 **【新增用户】** 按钮。
3. 在对话框中填写用户信息：

| 表单字段 | 说明 | 录入示例 |
|:---|:---|:---|
| **用户名** | 唯一登录账号，不可重复 | `zhangsan` |
| **显示名称** | 在系统界面（如侧边栏左下角和右上角）显示的名字 | `张三` |
| **角色标签** | 描述性标签，用于在个人信息上展示徽章 | `钳工` / `设计师` |
| **密码** | 用户初始登录密码（至少 6 位） | `123456` |
| **是否管理员** | 勾选后，该账号将绕过所有页面权限检查，直接拥有全站权限 | 保持未勾选（普通员工） |
| **是否激活** | 关闭后此用户将被停用，无法登录系统 | 保持开启 |

4. 填写完毕后点击“确定”保存。

## 分配页面权限

系统提供了精细的页面级权限分配矩阵。非管理员账号必须显式分配权限才能访问对应的页面：

1. 在用户列表中找到目标用户，点击右侧的 **【权限】** 按钮。
2. 在弹出的权限矩阵中，针对系统内的每个页面进行配置：
   - **完全不可见**：将“可见”和“可编辑”两个开关都关闭。该用户登录后，左侧菜单将不会渲染此菜单项，直接通过 URL 访问也会被路由拦截。
   - **只读权限**：仅开启“可见”开关，保持“可编辑”关闭。用户能正常浏览列表和进入详情页，但页面上的新增、编辑、删除、导入、导出等写入按钮将全部被禁用，后端接口也会进行 403 拦截。
   - **可编辑权限**：将“可见”和“可编辑”开关全部开启，该用户拥有该模块完整的增删改查权限。

| 实际岗位角色 | 仪表台 | 订单管理 | 客户管理 | 库存管理 | 图纸管理 | 工艺流程 | 用户管理 | 通知中心 | 系统设置 | 外协管理 |

| **车间操作工** | 可见 | 可编辑 | 只读 | 可编辑 | 只读 | 只读 | 不可见 | 可见 | 不可见 | 不可见 |

| **库房管理员** | 可见 | 只读 | 不可见 | 可编辑 | 不可见 | 不可见 | 不可见 | 可见 | 不可见 | 不可见 |

## 管理员防锁死保护

为避免管理员在配置自身权限时发生误操作（如关闭了自己的“用户管理”权限，导致再也无法进入该页面）：
* **前端锁定**：在管理员修改自身账号的权限时，前端的“用户管理”开关会被强制锁定为“开启”状态且不可点按。
* **后端守护**：系统后端强制禁止删除数据库中仅存的最后一个管理员账户（若尝试删除，接口将报错 `Cannot delete the last admin`）。

## 删除用户

在用户列表中找到对应用户，点击右侧的 **【删除】** 按钮即可。删除操作将级联删除该用户关联的页面权限行。

## 修改与重置密码

1. **用户自行修改密码**：
   - 登录系统后，点击左侧菜单底部的 **【系统设置】**。
   - 在“修改密码”卡片中，输入当前密码和新密码（至少 6 位）进行更改。
2. **管理员重置他人密码**：
   - 管理员进入 **【用户管理】** 页面。
   - 编辑目标用户，在密码输入框中输入新的密码，保存即可。

## 故障排除与数据库重置

| 遇到的问题 | 可能的原因 | 解决方案 |
|:---|:---|:---|
| 用户登录后看不到任何菜单 | 未分配任何权限。 | 请管理员进入用户管理，为其分配至少一个页面的“可见”权限。 |
| 用户能看页面但“新增”等按钮点击没反应或报错 403 | 页面权限仅为只读。 | 请检查该用户在权限配置中是否开启了“可编辑”开关。 |
| 管理员忘记了 admin 账号的密码，无法登录系统 | 数据库凭据丢失，无法进入后台管理。 | 1. 运行 `docker-compose down -v` 清理挂载的 PostgreSQL 卷以清空所有数据；<br>2. 重新启动服务 `docker-compose up`；<br>3. 在终端执行 `docker-compose exec backend python seed.py` 重新生成默认密码为 `123` 的初始 admin 账号。 |
