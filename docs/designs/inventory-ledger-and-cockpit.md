# CEO Plan: 库存流水账本重做 + 运营驾驶舱（G1 汇易通 MES）

## Vision

### 10x Check
10x 版本不是"库存管理软件"，而是"车间的单一事实来源"：班前会投屏的驾驶舱直接回答"今天什么会出问题"（缺料/逾期/外协超期/待办）；出入库实时反映到驾驶舱和订单页；全车间无纸质台账。**本次交付的终态达到 10x 愿景的桌面端全部与数据实时一致性，但不包含车间平板专用操作页面**（唯一缓办的 10x 组件，二期补上后闭环）。

### Platonic Ideal
三端同一套真相：办公室浏览器管全局、驾驶舱投屏管风险、车间平板管操作。工人不懂"库存管理"，只在干活的地方按"领料"；老板不懂"报表"，打开面板第一眼是"今天什么会出事"。库存量的本质是事件流水的推导结果（任何时刻可审计、可回溯），而不是一个可手改的字段。

## Core Insight (Eureka)
G1 不是通用 WMS，是订单驱动的项目型非标制造。库存真正缺的不是功能数量，是**事件模型**——把"改数字"变成"记事件"。仪表盘同理：风险优先，不是数字罗列。对标范式：InvenTree（流水账+物料主数据+库位+批次+分配）、qcadoo/OpenMES（工单驱动）。

## Implementation Approach
APPROACH B（一次到位）+ **服务层单一写入口**（D10）。Completeness: 9/10。
**架构铁律：库存写入只经 `services/inventory_service.py`**——行锁（with_for_update）+ 流水插入 + 缓存列刷新在同一事务；orders.py 4 处散写与 2 份重复 `check_inventory_alert` 收敛进服务层；新代码强制 SQLAlchemy 2.0 `select()` 语法；`except Exception: print()` 模式禁止延续（通知是旁路，失败记结构化日志但不阻断库存主流程）。

## Data Model Sketch

```
StockMovement 库存流水（单一事实来源，append-only）
  id, item_id FK, batch_no nullable, unit_cost nullable
  type: OPENING | INBOUND | OUTBOUND(领料) | RETURN(退料) | ADJUSTMENT(盘点差额)
  source_type: manual | order | purchase | stocktake
  source_id nullable; quantity(带符号); balance_after(快照)
  operator_id FK users, note, created_at
  索引: (item_id, created_at), (order_id/source_id), (type)
  推导规则：item.total = SUM(quantity)；reserved = SUM(有效预留)。
  total/reserved 列保留为同事务刷新的缓存列，唯一写入者是服务层。

领料-预留转换矩阵（D19）
  领料带订单 → 同事务扣减该订单对应预留行（部分领料按实际数消耗预留）
  超领（超过预留/无预留）→ 允许，写未匹配 OUTBOUND（source_type=order 但无预留行）
  退料 → RETURN，按需恢复预留或直接入账

BOM / BOMItem 用料模板（与 ProcessFlow is_template 同构）
  BOM: id, name, product_type(受控枚举), version, is_active, created_at
  BOMItem: bom_id FK, item_id FK, quantity_per_set, note
  匹配键（D17）：Order.product_type 与 BOM.product_type 两端均为受控枚举
  （下拉选已有类型，禁止自由文本）；无匹配时建单弹层提示 + 手动选 BOM 兜底。

PurchaseOrder 采购单（雏形状态机）
  id, po_no, vendor_id nullable, status: draft | ordered | received | closed
  item_id FK, quantity, received_quantity(部分到货，D19),
  expected_date, received_at, received_by
  到货确认写入实际收到数 → 生成 INBOUND(source_type=purchase) → 全部到齐才 closed
  雏形阶段一张采购单仅含一个物料，补货清单逐项生成。

InventoryItem 增量
  category, location, min_stock(接替 alert_threshold), is_archived(归档替代删除, D19)
  归档规则：存在流水的物料禁止 DELETE，只能 is_archived=1（保护审计链）；
  订单同理——存在流水的订单禁止删除（D19）。
```

## Auth Fix Definition（含 D12/D19 并入项）
1. 六个 Router 统一挂 `dependencies=[Depends(get_current_user)]`；
2. 登录与 `/auth/me` 改用 `UserResponse`，停止返回 `password_hash`；
3. `SECRET_KEY`/`DATABASE_URL` 去默认值，缺失即启动失败；
4. `main.py`/`documents.py`/`notifications.py`/`users.py` 中 4 处裸 `jwt.decode` 统一改走 `routers/auth.py:get_current_user`（其已含 is_active 校验）；
5. **P0-5 完整修复**：上传路径净化（拒绝 `../` 与分隔符）+ `/uploads` 改鉴权下载（不再匿名 StaticFiles 直挂）+ SVG 禁直出/消毒；
6. 实现 `/auth/refresh` 与 `/auth/logout`（前端已在调用，现状 404）；
7. 删除 `index.html` 的 Tailwind CDN 脚本；
8. 新端点权限两档（D13）：领料/退料/报工挂 `can_edit('inventory')`；物料主数据/盘点/Excel 导入/采购管理挂 `is_admin`。

## Cutover Plan（存量数据迁移）
1. 迁移前强制 `pg_dump` 全库备份；
2. 每个存量 `InventoryItem` 生成一条 `OPENING` 流水（quantity=当前 total）；
3. 存量 `InventoryReservation` 全部保留继续生效；迁移前对 `(order_id, item_id)` 去重；
4. `alert_threshold → min_stock` 改名 + **同步 `UPDATE notification_rules` 的 condition_field 存量键与模板占位符**（否则存量规则静默失配，D19）；
5. 迁移脚本提供 `downgrade()`；先在 seed_mock 复制库演练（演练必须含第 4 条数据修复）；
6. 存量 `inventory_deducted=1` 订单不回溯补流水；
7. **迁移窗口写冻结**（停机或只读维护页）；cutover 后的回滚=恢复备份并接受丢失迁移后交易（不再宣称无损回滚，D19）。

## Delivery Sequence（单批次内部强制顺序）
1. **前置**：Alembic 基线重建为完整建表迁移（硬前置，现 baseline 只建索引）；
2. 鉴权止血（Auth Fix Definition 全部 8 项）；
3. 新表（StockMovement/BOM/BOMItem/PurchaseOrder）+ 索引 + 预留唯一约束（先去重）+ Cutover 迁移 + 盘点调整流程（录实盘数→系统算差额→ADJUSTMENT 流水，无审批流）；
4. 服务层 + 订单联动：建 `services/inventory_service.py` 单写入口；**退役 `deduct_order_inventory`/`rollback_order_inventory` 及 `inventory_deducted` 门控（D16——状态流转不再碰库存，防双重记账）**；删除订单释放预留；预警口径统一 `available = total − reserved`；**预警只在阈值穿越时触发**（比较变动前后，D19 防轰炸）；删除守卫（有流水禁删物料/订单）；
5. 库存操作 UI（入库/领料/退料/盘点）+ 订单页用料链路可视化；领料 SOP＝工序推进即录（D18，上线验收标准）；驾驶舱"已完成未领料"风险项兜底漏录；
6. 运营驾驶舱：风险清单（缺料/逾期/停滞工序/已完成未领料/待办）+ 趋势带 + 深链直达 + 口径 hover 说明；**60s 轮询兜底**（SSE 多 worker 缺陷不阻塞）；**趋势首日数据源用 Order 历史**（流水自上线起，图表明确标注"D19"）；
7. 扩围按序：BOM 模板（含 product_type 枚举校验）→ 采购雏形（含 received_quantity 部分到货）→ Excel 导入导出（部分成功+错误清单，10MB 上限，每 500 行一批）。

## Rollout / Rollback
- 上线窗口：低峰期，写冻结执行迁移（分钟级）；生产部署命令链补入 `alembic upgrade head`；
- 回滚路径：迁移窗口内=应用回退 + `alembic downgrade` + 恢复 pg_dump；**cutover 后=恢复备份 + 接受丢失迁移后交易**（D19 修正：不承诺上线后无损回滚）。
